# Подключение системы к выставлению счетов Kaspi

Сервис: **https://kaspi-invoice.ristart.kz**

Через него наша система выставляет клиенту счёт в Kaspi (клиенту приходит push в приложении Kaspi.kz, он оплачивает) и узнаёт, оплачен ли счёт.

---

## 1. Получить API-токен (один раз, в интерфейсе)

1. Откройте https://kaspi-invoice.ristart.kz.
2. Войдите **номером кассира** Kaspi Pay → введите код из SMS.
   - Номер владельца не подойдёт: Kaspi попросит пароль Kaspi.kz, и вход не пройдёт.
   - Кассира добавляет владелец: приложение Kaspi Pay → «Сотрудники» → добавить кассира.
3. Под карточкой с номером раскройте **«API-токен для подключения системы»** → **«Скопировать токен»**.
4. Сохраните токен в настройках нашей системы. Это ключ от выставления счетов от имени кассира — храните как пароль, не пересылайте в открытых чатах.

### Когда токен перестаёт работать

Токен живёт, пока жива сессия кассира в Kaspi. Она обрывается, если:

- кассир вошёл этим номером **в приложении Kaspi Pay** на телефоне или на другом устройстве;
- кто-то снова вошёл этим номером в веб-интерфейсе.

Признак — ответ `401` или ошибка «сессия истекла». Что делать: войти в интерфейс заново и скопировать новый токен.

> Совет: заведите **отдельного кассира только под интеграцию** и не входите его номером никуда, кроме этого сервиса.

## 2. Выставить счёт

```
POST https://kaspi-invoice.ristart.kz/api/invoice/create
Authorization: Bearer <токен>
Content-Type: application/json
```

```json
{
  "phoneNumber": "7071234567",
  "amount": 15000,
  "comment": "Оплата счёта №42"
}
```

| Поле | Обязательно | Описание |
|---|---|---|
| `phoneNumber` | да | Телефон клиента, **10 цифр без 7/+7** (`7071234567`). У клиента должен быть Kaspi.kz |
| `amount` | да | Сумма в тенге |
| `comment` | нет | Текст, который клиент увидит в счёте |

Пример:

```bash
curl -X POST https://kaspi-invoice.ristart.kz/api/invoice/create \
  -H "Authorization: Bearer $KASPI_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"phoneNumber":"7071234567","amount":15000,"comment":"Оплата счёта №42"}'
```

Успешный ответ (главное — `Data.QrOperationId`, сохраните его у себя рядом с заказом):

```json
{
  "StatusCode": 0,
  "Data": {
    "QrOperationId": 123456789,
    "Amount": 15000,
    "ClientMobile": "7071234567"
  }
}
```

Если `StatusCode` не `0` — счёт не создан, текст ошибки в `Message`.

### Проверить, есть ли у клиента Kaspi (необязательно, перед выставлением)

```
GET https://kaspi-invoice.ristart.kz/api/invoice/client-info?phoneNumber=7071234567
Authorization: Bearer <токен>
```

## 3. Узнать, оплачен ли счёт

### Вариант А — опрашивать статус

```
GET https://kaspi-invoice.ristart.kz/api/invoice/details?operationId=<QrOperationId>
Authorization: Bearer <токен>
```

Смотрите `Data.Status`:

| `Data.Status` | Что значит |
|---|---|
| `RemotePaymentCreated` | Счёт выставлен, клиент ещё не оплатил |
| `Processed` | **Оплачен** |
| `RemotePaymentCanceled` | Отменён |
| `RemotePaymentRejected` | Клиент отклонил |
| `Expired` | Истёк срок оплаты |

Опрашивайте не чаще раза в 5–10 секунд и прекращайте после финального статуса.

### Вариант Б — вебхук (сервис сам сообщит об оплате)

Сервис сам следит за каждым выставленным счётом и при смене статуса шлёт `POST` на адрес нашей системы. Чтобы включить, **передайте Динмухамеду URL приёма и секрет** — он пропишет их на сервере.

Тело запроса:

```json
{
  "event": "payment.success",
  "paymentId": "123456789",
  "type": "invoice",
  "status": "Processed",
  "statusDesc": "Операция проведена успешно",
  "amount": 15000,
  "timestamp": "2026-10-07T10:00:00.000Z"
}
```

| `event` | Когда |
|---|---|
| `payment.success` | Оплачен |
| `payment.failed` | Отменён или отклонён |
| `payment.expired` | Истёк срок |
| `payment.lost` | Сервис потерял связь с Kaspi (сессия кассира оборвалась) — статус проверить вручную и обновить токен |

`paymentId` — это `QrOperationId` из ответа на создание счёта.

Подпись: заголовок `X-Webhook-Signature: sha256=<hex>` — HMAC-SHA256 тела запроса с секретом. Проверяйте её, чтобы чужие запросы не отметили заказ оплаченным. Пример проверки — в [API.md](./API.md#подпись-hmac).

Если наш адрес не ответил, сервис повторит отправку ещё 2 раза (через 5 и 30 секунд).

---

## 4. Отменить счёт (пока не оплачен)

```
POST https://kaspi-invoice.ristart.kz/api/invoice/cancel
Authorization: Bearer <токен>
Content-Type: application/json

{ "operationId": 123456789 }
```

---

## Частые ошибки

| Ответ | Причина | Что делать |
|---|---|---|
| `401 Missing X-Token-SN header.` | Не передан токен | Добавить `Authorization: Bearer <токен>` |
| `401 Invalid API token.` | Токен обрезан или испорчен при копировании | Скопировать заново целиком |
| `401 Invalid or expired vtokenSecret` | Токен от другого сервера или старый | Войти в интерфейс, скопировать новый |
| `StatusCode: -101001` | Кассир вошёл с другого устройства, сессия вытеснена | Войти в интерфейс, скопировать новый токен |

Полное описание всех методов — [API.md](./API.md). Вместо `Authorization: Bearer` там везде можно использовать старые три заголовка `X-Token-SN`, `X-Profile-Id`, `X-Vtoken-Secret` — работают оба способа.
